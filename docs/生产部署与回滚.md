# 生产部署、备份与回滚

本文件用于生产前演练。生产运行时必须使用 PostgreSQL 和 Redis，禁止把 SQLite 当作应用数据库回退。

## 环境变量

```env
ENVIRONMENT=production
DATABASE_URL=postgresql+asyncpg://<user>:<password>@<host>:5432/<database>
REDIS_URL=redis://:<password>@<host>:6379/0
JWT_SECRET=<至少 32 字符的随机值>
TRUSTED_HOSTS_ENABLED=true
TRUSTED_HOSTS=["admin.example.com"]
API_DOCS_ENABLED=false
VITE_DEMO_LOGIN_ENABLED=false
```

应用启动会拒绝默认 JWT Secret、缺失 PostgreSQL/Redis、未启用 Trusted Hosts 或生产 API 文档开启的配置。连接串只通过受保护的 Secret 管理，不写入日志、截图和 Git。

## 进程拓扑

反向代理负责 TLS、域名和静态前端；FastAPI 只监听内网；Worker 和 Scheduler 使用相同版本、相同环境变量和 Redis 队列 `background`。发布顺序为：构建前端、停止旧 Worker、运行 `alembic upgrade head`、启动 API、等待 `/api/v1/health/ready`、启动 Worker/Scheduler、执行验收脚本。

## 数据库迁移

```powershell
.venv\Scripts\python.exe -m server.app migrate --dry-run
.venv\Scripts\python.exe -m alembic upgrade head
```

禁止手工 `CREATE TABLE` 或 `ALTER TABLE`。迁移失败时停止发布，保留旧应用和数据库现场，不执行未经验证的 downgrade。

## PostgreSQL 备份与恢复演练

```powershell
pg_dump --format=custom --no-owner --file=backup.dump "$env:PRODUCTION_DATABASE_URL"
createdb fastapi_admin_restore
pg_restore --clean --if-exists --no-owner --dbname="$env:RESTORE_DATABASE_URL" backup.dump
.venv\Scripts\python.exe -m alembic upgrade head
```

恢复演练必须使用隔离数据库，确认 Users、Roles、Permissions、Audit Logs、Tasks 和 Alembic 版本后，调用 `/api/v1/health/ready` 和受保护的 `/api/v1/health/detail`。不得对 Laragon 用户管理的生产服务执行自动重启或改配置。

## Redis、Worker 和 Scheduler

Redis 不可用时，健康 ready 变为 degraded；生产登录、Refresh/Revoke、写操作和破坏性操作 fail-closed。恢复 Redis 后重新检查登录、限流、任务发布和任务恢复。

```powershell
.venv\Scripts\python.exe -m server.app worker
.venv\Scripts\python.exe -m server.app scheduler
```

停止发布时先让 Worker 排空，再停止 Scheduler，确认 running 任务按 lease 恢复；不要按进程名杀掉非本项目进程。

## 回滚

代码回滚必须使用已验证的上一版本制品。数据库迁移只能回滚到已经通过恢复演练的兼容版本；优先使用向后兼容迁移和旧应用可读的新字段。若迁移不可逆，使用 PostgreSQL backup/restore 到隔离库并切换连接配置，不在生产库直接试错。

## 验收

执行 `scripts/production-acceptance.ps1`，并记录配置门禁、健康检查、认证、权限、审计、CSP、迁移、备份恢复、Redis 故障和 Worker/Scheduler 恢复结果。外部 Telemetry 本阶段明确不在验收范围内。
