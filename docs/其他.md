对，下一步就应该锁定 **Resource Engine Contract**，而不是继续开发页面。这里最关键的是避免 Python 和 TypeScript 各维护一套“相似但逐渐漂移”的定义。

我建议 Resource Engine 本身也遵循你前面确定的 **Contract First**：

> **Python Resource Definition 是服务端事实来源 → 输出 Resource Manifest → TypeScript 只维护 Renderer/Runtime 类型；API DTO 仍然由 OpenAPI 自动生成。**

这样 CRUD Generator、Vue Admin、权限、Query Engine 都围绕同一份 Resource Metadata 工作。

## 一、先确定 Resource Engine 的分层

不要做成一个巨大的 `ResourceDefinition`。建议拆成：

```text
Resource Engine
│
├── ResourceDefinition
│
├── FieldDefinition
│
├── TableDefinition
│   ├── ColumnDefinition
│   ├── FilterDefinition
│   └── TableAction
│
├── FormDefinition
│   ├── FormSection
│   └── FieldDefinition
│
├── ActionDefinition
│
├── RelationDefinition
│
├── PermissionDefinition
│
├── QueryDefinition
│
└── ResourceManifest
```

核心关系：

```text
                 ResourceDefinition
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
      Table            Form           Relations
        │               │
   ┌────┼────┐       Fields
 Columns Filters
        │
      Actions

                 ↓ compile

             ResourceManifest
                    │
                    ▼
                Vue Admin
```

这里增加一个很重要的概念：

**Definition ≠ Manifest。**

`Definition` 可以包含 Python callback、SQLAlchemy Model、Policy class 等服务端对象；这些东西不能传给浏览器。

真正给 Vue 的是经过编译后的：

```text
ResourceManifest
```

纯 JSON、可序列化、无服务端代码。

# 二、ResourceDefinition

Python 建议：

```python
@dataclass
class ResourceDefinition:
    name: str
    label: str
    label_plural: str | None = None

    model: type[Base] | None = None

    icon: str | None = None
    description: str | None = None

    route: str | None = None
    api_endpoint: str | None = None

    navigation: NavigationDefinition | None = None

    permissions: PermissionDefinition | None = None
    query: QueryDefinition | None = None

    table: TableDefinition | None = None

    create_form: FormDefinition | None = None
    edit_form: FormDefinition | None = None
    detail: DetailDefinition | None = None

    relations: list[RelationDefinition] = field(
        default_factory=list
    )

    actions: list[ActionDefinition] = field(
        default_factory=list
    )

    features: ResourceFeatures = field(
        default_factory=ResourceFeatures
    )
```

例如：

```python
class UserResource(Resource):
    name = "users"
    label = "User"
    model = User

    permissions = Permissions(
        view="users.view",
        create="users.create",
        update="users.update",
        delete="users.delete",
    )
```

不要到处增加：

```text
can_create
can_update
can_delete
enable_export
enable_import
...
```

统一：

```python
@dataclass
class ResourceFeatures:
    create: bool = True

    import_: bool = False
    export: bool = False

    search: bool = True

```

以后：

```python
features = ResourceFeatures(
    import_=True,
    export=True,
    soft_delete=True,
)
```

# 四、FieldDefinition 是最关键的 Contract

Field 不应该只是 Form Field。

同一个 Field Metadata 可以服务：

```text
Database
API
Form
Table
Filter
Detail
Generator
```

基础定义：

```python
@dataclass
class FieldDefinition:
    name: str
    type: FieldType

    label: str | None = None
    description: str | None = None

    required: bool = False
    nullable: bool = True

    readonly: bool = False
    disabled: bool = False

    default: Any = None

    placeholder: str | None = None

    searchable: bool = False
    sortable: bool = False
    filterable: bool = False

    hidden: bool = False

    visible_on_list: bool = True
    visible_on_create: bool = True
    visible_on_edit: bool = True
    visible_on_detail: bool = True

    validation: list[ValidationRule] = field(
        default_factory=list
    )

    ui: FieldUI | None = None

    permission: str | None = None
```

---

# 五、FieldType 不要无限增长

基础类型保持稳定：

```python
class FieldType(StrEnum):
    STRING = "string"
    TEXT = "text"

    INTEGER = "integer"
    FLOAT = "float"
    DECIMAL = "decimal"

    BOOLEAN = "boolean"

    DATE = "date"
    DATETIME = "datetime"
    TIME = "time"

    ENUM = "enum"

    EMAIL = "email"
    URL = "url"
    PASSWORD = "password"

    JSON = "json"

    FILE = "file"
    IMAGE = "image"

    RELATION = "relation"
```

RichText、Markdown、Code 不一定需要成为真正的数据类型。

它们本质上仍然：

```text
STRING / TEXT
```

只是：

```python
ui.widget = "markdown"
```

或者：

```python
ui.widget = "rich-text"
```

这是一个非常重要的设计。

否则最后会出现几十种 FieldType。

---

# 六、数据类型和 UI Widget 分离

推荐：

```python
Field(
    name="content",
    type="text",

    ui=FieldUI(
        widget="rich-text"
    )
)
```

而不是：

```python
type="rich_text"
```

因此：

```text
Data Type          UI Widget

string       →     input
string       →     email
string       →     password

text         →     textarea
text         →     markdown
text         →     rich-text
text         →     code

boolean      →     checkbox
boolean      →     switch

enum         →     select
enum         →     radio

relation     →     select
relation     →     combobox
relation     →     autocomplete
```

这会让 Field Engine 稳定很多。

# 七、FieldUI

```python
@dataclass
class FieldUI:
    widget: str | None = None

    width: str | None = None

    prefix: str | None = None
    suffix: str | None = None

    icon: str | None = None

    rows: int | None = None

    clearable: bool = True

    options: list[OptionDefinition] | None = None
```

不要把 Tailwind class 从服务器直接传下来。

禁止：

```python
class_name="col-span-4 text-red-500"
```

否则服务端开始控制 Vue UI implementation。

应该传语义：

```python
width="half"
```

前端决定：

```text
half → md:grid-cols...
```

# 八、ValidationDefinition

不要让前端自己猜验证规则。

```python
@dataclass
class ValidationRule:

    message: str | None = None
```

例如：

```python
validation=[
    ValidationRule("min_length", 3),
```

Manifest：

```json
{
  "validation": [
    {
      "type": "min_length",

      "type": "max_length",
      "value": 64
    }
  ]
}
```

但是：

> 前端 Validation 只改善 UX。

最终验证仍然必须：

```text
Pydantic / Service
```

负责。

# 十、ColumnDefinition

Column 和 Field 不应该完全等同。

例如：

```text
first_name
last_name
```

可以在 Table 显示：

```text
Full Name
```

因此：

```python
@dataclass
class ColumnDefinition:
    key: str

    label: str | None = None

    field: str | None = None

    sortable: bool = False

    searchable: bool = False

    visible: bool = True

    toggleable: bool = True

    format: str | None = None

    align: Literal[
        "left",
        "center",
        "right"
    ] = "left"

    width: int | None = None
```

例如：

```python
Column(
    key="created_at",
    field="created_at",
    label="Created",
    sortable=True,
    format="datetime",
)
```

---

# 十一、Formatter 不能传 JS/Python

Manifest 禁止：

```text
formatter: function(...)
```

应该：

```text
format: "datetime"
```

或者：

```text
format: "currency"
```

前端注册：

```ts
formatterRegistry.register(
  "datetime",
  datetimeFormatter
)
```

因此整个 Resource Engine 应该大量采用：

> **Registry + Identifier**

而不是：

> Backend → Frontend 传 executable code。

```python
@dataclass

    options: list[OptionDefinition] | None = None

    default: Any = None
```

基础 Filter：

```text

multi_select

boolean

date_range
```

例如：

```python
Filter(
```

# 十三、QueryDefinition

Filter UI 和 Query Security 必须分开。

```python
@dataclass
class QueryDefinition:
    searchable: list[str]

    sortable: list[str]

    filterable: dict[str, FilterPolicy]

    default_sort: list[SortDefinition]

    max_page_size: int = 100

    allowed_includes: list[str] = field(
        default_factory=list
    )
```

这是服务器安全边界。

即使 Vue 修改请求：

```text
?sort=password_hash
```

如果不在：

```python
sortable
```

直接拒绝。

# 十四、FormDefinition

不要只定义：

```text
fields[]
```

应该支持布局：

```python
@dataclass
class FormDefinition:
    sections: list[FormSection]

    columns: int = 1

    submit_label: str | None = None
```

Section：

```python
@dataclass
class FormSection:
    key: str

    label: str | None = None

    description: str | None = None

    fields: list[str] = field(
        default_factory=list
    )

    columns: int = 1

    collapsible: bool = False
```

例如：

```text
Basic Information
┌──────────────────────────────┐
│ Username        Email        │
│                              │
│ Status          Role         │
└──────────────────────────────┘

Profile
┌──────────────────────────────┐
│ Bio                          │
│                              │
└──────────────────────────────┘
```

# 十五、不要把 CSS Grid 写进 Schema

推荐：

```python
FormSection(
    columns=2
)
```

Field：

```python
ui=FieldUI(
    width="full"
)
```

而不是：

```text
grid-cols-2
col-span-2
md:col-span-1
```

Resource Manifest 必须保持 UI Framework Independent 的语义层。

虽然当前使用 shadcn-vue，但以后不应该让 Resource Contract 被 Tailwind class 污染。

# 十六、ActionDefinition

Action 是第二个非常关键的设计。

```python
@dataclass
class ActionDefinition:
    name: str
    label: str

    icon: str | None = None

    type: ActionType = ActionType.API

    endpoint: str | None = None
    method: str | None = None

    permission: str | None = None

    confirmation: ConfirmationDefinition | None = None

    form: FormDefinition | None = None

    refresh: bool = True

    variant: str = "default"
```

例如：

```python
Action(
    name="disable",
    label="Disable",
    endpoint="/api/v1/users/{id}/disable",
    method="POST",
    permission="users.update",
    confirmation=Confirmation(
        title="Disable user?",
    ),
)
```

# 十七、Action 分类

至少：

```text
Row Action

Bulk Action

Page Action

Global Action
```

例如：

```text
User List

[Create User]

William
    View
    Edit
    Disable
    Delete
```

Bulk：

```text
[x] User 1
[x] User 2
[x] User 3

Bulk:
    Disable
    Delete
    Export
```

全部由同一个 Action Engine 驱动。

# 十八、Action 不能只靠前端 permission

前端：

```text
permission="users.delete"
```

只负责隐藏/禁用按钮。

后端 endpoint：

```text
Depends(require_permission("users.delete"))
```

仍然必须验证。

原则：

> UI Permission ≠ Security Boundary。

# 十九、RelationDefinition

建议第一版支持：

```text
belongs_to
has_one
has_many
many_to_many
```

Python：

```python
@dataclass
class RelationDefinition:
    name: str

    type: RelationType

    resource: str

    local_key: str | None = None
    foreign_key: str | None = None

    display_field: str = "name"

    searchable: bool = True

    preload: bool = False
```

例如：

```python
Relation(
    name="roles",
    type="many_to_many",
    resource="roles",
    display_field="name",
)
```

前端就可以自动生成：

```text
Role

[ Search roles...       ▼ ]
```

# 二十、Relation 不应该直接暴露数据库细节给前端

后端 Definition 可以知道：

```text
foreign_key
local_key
```

但 Resource Manifest 没必要全部发送。

Manifest 应该更多是：

```json
{
  "name": "roles",
  "type": "many_to_many",
  "resource": "roles",
  "displayField": "name",
  "searchable": true
}
```

数据库实现仍留在服务器。

# 二十三、Resource Manifest

这是 Python → Vue 真正的 Contract。

例如：

```json
{
  "name": "users",
  "label": "User",
  "labelPlural": "Users",

  "routes": {
    "list": "/users",
    "create": "/users/create"
  },

  "api": {
    "base": "/api/v1/users"
  },

  "features": {
    "create": true,
    "update": true,
    "delete": true,
    "export": true
  },

  "table": {},

  "forms": {
    "create": {},
    "edit": {}
  },

  "actions": [],

  "relations": []
}
```

这个 Manifest 必须满足：

```text
JSON Serializable
Versioned
Validated
No Python Objects
No Functions
No SQLAlchemy Metadata
No Secrets
```

---

# 二十四、Manifest 必须版本化

现在就加：

```json
{
  "schemaVersion": "1.0"
}
```

否则以后 Resource Engine v2 改 Field Schema，旧 Admin/插件无法判断兼容性。

建议：

```text
Resource Manifest v1
```

作为独立 Contract。

---

# 二十五、TypeScript 不应该重新手写业务 Resource 类型

TypeScript 只定义 Runtime Manifest Contract：

```ts
export interface ResourceManifest {
  schemaVersion: string

  name: string
  label: string
  labelPlural?: string

  features: ResourceFeatures

  table?: TableDefinition

  forms?: {
    create?: FormDefinition
    edit?: FormDefinition
  }

  actions: ActionDefinition[]
  relations: RelationDefinition[]
}
```

Field：

```ts
export interface FieldDefinition {
  name: string

  type: FieldType

  label?: string
  description?: string

  required: boolean
  nullable: boolean

  readonly: boolean
  disabled: boolean

  searchable: boolean
  sortable: boolean
  filterable: boolean

  validation: ValidationRule[]

  ui?: FieldUI
}
```

但是最好进一步做到：

```text
Python Manifest JSON Schema
            ↓
TypeScript Generate
```

避免这部分最终也人工漂移。

建议提供：

```text
      ↓

```

Resource Manifest 大多数时候不会频繁变化。

可以：

```text

+

```

并支持：

```text

```

以后 Resource 改变：

```text
      ↓

```

# 三十三、Generator 与 Resource Engine 的关系

Generator 不应该自己重新定义字段系统。

必须：

```text
Database Introspection
        ↓
FieldDefinition
        ↓
ResourceDefinition
        ↓
Generator
```

例如数据库：

```text
varchar(255)
nullable=false
unique=true
```

映射：

```text
FieldDefinition

type=string
required=true
nullable=false
```

再由 Generator 生成：

```text
Pydantic
Resource
Form
Table
Filter
```

这样 Generator 与 Runtime 使用同一个 Metadata Model。

# 三十四、SQLAlchemy → Resource 推断

可以自动推断：

# 三十五、不要过度自动推断

例如：

```text
String(255)
```

无法可靠判断：

```text
URL?
Email?
Username?
Title?
```

所以 AI Enhancement 可以建议：

```text
email column
→ widget=email
```

但 deterministic generator 的默认：

```text
String
→ input
```

保持稳定。

# 三十六、建议增加 Resource Lifecycle Hooks

但 Hook 只存在后端 Definition，不进入 Manifest。

例如：

```python
class UserResource(Resource):

    async def before_create(self, data):
        ...

    async def after_create(self, user):
        ...

    async def before_update(self, user, data):
        ...

    async def after_update(self, user):
        ...

    async def before_delete(self, user):
        ...

    async def after_delete(self, user):
        ...
```

不过这里要规定：

> 复杂业务不要塞大量 Hook。

复杂操作进入 Service。

Hook 主要用于 Resource 生命周期扩展。

# 三十八、Bulk Action 事务

必须明确：

```text
Bulk Delete
Bulk Update
Bulk Disable
```

支持策略：

```text
atomic
best_effort
```

`atomic`：

```text
100 records
    ↓
1 failed
    ↓
Rollback all
```

`best_effort`：

```text
100 records
    ↓
97 success
3 failed
```

## 最终要锁死的三层 Contract

我建议现在正式把整个系统的 Contract 分成三个，不要混：

```text
① Database Contract

SQLAlchemy Model
        ↓
Alembic
        ↓
Database


② API Contract

Pydantic
   ↓
OpenAPI
   ↓
Generated TypeScript SDK


③ Admin UI Contract

ResourceDefinition
        ↓
Resource Manifest
        ↓
Generated Manifest Types
        ↓
Vue Resource Engine
```

三者关系：

```text
                  SQLAlchemy
                      │
                Resource Metadata
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
       Pydantic             ResourceDefinition
          │                       │
          ▼                       ▼
       OpenAPI              Manifest Compiler
          │                       │
          ▼                       ▼
      TS API SDK            Resource Manifest
          │                       │
          └───────────┬───────────┘
                      ▼
                  Vue Admin
```

这比简单做一个：

```text
Python Resource
↔
TypeScript Resource
```

更稳。

**API 数据类型由 OpenAPI 管；Admin UI 元数据由 Resource Manifest 管；数据库结构由 SQLAlchemy/Alembic 管。三者各自只有一个事实来源。**

把这一层锁定之后，下一阶段才应该开始真正写 `ResourceDefinition`、`FieldDefinition` 等 Python 类型以及对应的 **Resource Manifest v1 JSON Schema**。这一步完成以后，CRUD Generator 的输入格式基本就不会再大改。
