# FastAPI Vue Shadcn Admin 对接开发指南（AI 友好版）

本文档是新业务项目接入本后台底座的执行手册。AI 开始修改代码前，应先读取本文档、`docs/项目约束.md` 和 `docs/阶段开发计划.md`，再检查现有模块中最接近的实现。默认原则是：复用 Resource Engine，优先写 Contract，不为普通资源编写专用 Vue 页面。

## 1. 项目定位

本项目提供可复用的后台基础设施：认证、JWT、RBAC、Data Scope、审计、健康检查、任务队列、模块注册、OpenAPI/TypeScript SDK、JSON 多语言和通用资源页面。

推荐技术栈：

- 后端：FastAPI、SQLAlchemy Async、Alembic、PostgreSQL、Redis
- 前端：Vue 3、Vite、TypeScript、Vue Router、Pinia、shadcn-vue
- 数据访问：Router → Service → Repository → SQLAlchemy → Database
- 普通资源：Resource Contract → Manifest → 通用列表/表单/权限/菜单

禁止用 SQLite 代替项目约定的 PostgreSQL 运行数据库。

## 1.1 前后端 URL 边界

- 后台前端统一使用 `/admin/*`，例如 `/admin/users`、`/admin/departments`。
- 根路径 `/` 预留给未来 C 端页面；当前根入口会显式进入 `/admin/`。
- 后端 API 保持 `/api/v1/*`，例如 `/api/v1/departments`，不增加 `/admin` 前缀。
- Scalar 保持 `/docs/scalar`，OpenAPI 保持 `/openapi.json`。
- 旧 `/users`、`/roles`、`/departments`、`/settings` 等路径无兼容跳转，直接按前端 404 处理。

## 2. AI 开发前置检查

```text
1. 读取 docs/项目约束.md
2. 读取 docs/阶段开发计划.md
3. 检查 server/app/modules 中是否已有相似模块
4. 检查 server/app/core/resources/definitions.py 的资源定义
5. 检查 admin/src/locales/<locale>/ 下对应命名空间
6. 先写测试，再修改生产代码
7. 运行前后端测试、类型检查和构建
```

不要凭空创建全局 `models/`、`services/`、`repositories/` 分层；新业务模块使用垂直模块目录，并在资源确实复杂时才增加专用前端页面。

## 3. 新增普通资源的最短路径

以 `Departments` 为例：

### 3.1 后端模型和迁移

```text
server/app/modules/departments/
├── model.py
├── repository.py
├── schemas.py
├── service.py
└── router.py
```

要求：

- SQLAlchemy 模型使用 PostgreSQL 兼容类型。
- 新表必须有 Alembic migration。
- 列表 API 必须支持分页、搜索、排序和权限过滤。
- 删除、批量删除等写操作必须经过权限检查并写审计日志。

### 3.2 注册 Resource Contract

在 `server/app/core/resources/definitions.py` 中定义：

```python
ResourceDefinition(
    name="departments",
    label="departments.label",
    label_plural="departments.labelPlural",
    api_base="/api/v1/departments",
    route="/admin/departments",
    permissions={
        "view": "departments.view",
        "create": "departments.create",
        "update": "departments.update",
        "delete": "departments.delete",
    },
    fields=(...),
)
```

同时接入：

- `RESOURCE_DEFINITIONS`
- 后端路由注册
- 权限目录和默认管理员权限
- 模块 Provider（若该资源有启动或关闭生命周期）
- 资源菜单权限

详情页约定：

- `ResourceFeatures.detail` 保持为 `True` 时生成通用详情路由。
- Manifest 的 `routes.detail` 统一使用 `${routes.list}/:id`，前端通过资源 Adapter 的 `get(id)` 加载详情。
- 普通资源使用 `GenericResourceDetailPage`；只有关系编辑、多步骤流程或非 CRUD 交互才编写专用详情页。
- 详情页表单字段必须来自 Contract 的 `forms.edit.fields`，只读字段不得进入更新请求。

### 3.3 前端多语言

每个资源必须提供：

```text
admin/src/locales/zh-CN/departments.json
admin/src/locales/en/departments.json
```

示例：

```json
{
  "departments": {
    "label": "部门",
    "labelPlural": "部门管理",
    "title": "部门管理",
    "description": "管理组织部门。"
  }
}
```

英文文件必须有同样的 key。禁止在 Vue 模板中硬编码用户可见文案，禁止输出 `users.labelPlural` 这类未解析键名。

### 3.4 前端页面

普通资源直接使用 `GenericResourcePage` 和资源路由，不新增专用页面。只有以下情况才创建专用页面：

- 复杂关系编辑器；
- 多步骤工作流；
- 非 CRUD 的业务操作；
- 资源 Contract 无法表达的交互。

## 4. 权限和数据范围

权限命名格式：`<resource>.<action>`，例如：

```text
departments.view
departments.create
departments.update
departments.delete
```

前端只负责体验层 Permission Guard，后端必须再次校验权限。Data Scope 必须在 Service/Repository 查询层生效，不能只在前端隐藏按钮。

## 5. API 和 SDK

后端 OpenAPI 是接口事实来源：

```text
http://127.0.0.1:8012/openapi.json
```

生成 SDK：

```powershell
cd admin
pnpm generate:sdk
pnpm generate:sdk:check
```

前端业务代码通过 API Adapter 调用 SDK，不直接散落 `fetch`。Adapter 应统一处理 token、错误、分页和响应格式。

## 6. 多语言和命名空间加载

使用 `admin/src/locales/<locale>/<namespace>.json`。通用文案放在 `common.json`，模块文案放在模块命名空间。进入资源路由时必须加载资源命名空间；Shell 使用的 Users、Roles、Departments、Auth 命名空间由共享基线统一预加载。

新增语言时必须：

1. 增加语言目录；
2. 为每个模块补齐 JSON；
3. 更新 `SupportedLocale`；
4. 增加 key 对齐测试；
5. 手动检查登录、菜单、表格、退出登录和错误提示。

## 7. 本地运行

```powershell
# API
.\.venv\Scripts\python.exe -m uvicorn server.app.main:app --host 0.0.0.0 --port 8012

# Frontend
cd admin
pnpm dev -- --host 0.0.0.0
```

需要 PostgreSQL 和 Redis。健康检查：

```text
http://127.0.0.1:8012/api/v1/health
```

## 8. 验收清单

```text
[ ] PostgreSQL migration 可在干净数据库执行
[ ] API 列表、详情、创建、更新、删除符合权限
[ ] 前端列表支持搜索、分页、排序和状态过滤
[ ] 不显示内部 id，除非业务明确要求
[ ] 中英文 JSON key 对齐
[ ] 菜单不显示原始 i18n key
[ ] 用户中心设置和退出登录可用
[ ] 审计日志覆盖写操作
[ ] SDK 已重新生成并通过 check
[ ] pnpm typecheck 通过
[ ] pnpm test 通过
[ ] pnpm build 通过
[ ] server/tests 全部通过
```

## 9. 给 AI 的输出格式

AI 完成一个模块后，必须报告：

1. 修改的文件；
2. 新增的 API、权限和迁移；
3. 是否复用了 Resource Contract；
4. 多语言命名空间；
5. 测试和构建结果；
6. 未实现或需要人工决策的部分。

禁止只报告“已完成”，必须给出可复核的命令和结果。
