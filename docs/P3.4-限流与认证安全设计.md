# P3.4 Rate Limit 与认证安全设计

**状态：** 基础实现已完成，待运行时集成验证

## 1. 范围

本阶段建立可复用的 Rate Limit Engine，并补齐 JWT Refresh/Revoke、登录限流和认证错误响应。

## 2. Rate Limit Engine

- 实现位置：`server/app/core/rate_limit.py`。
- 存储：Redis `INCR + EXPIRE`，Key 使用策略名、身份和路由维度的摘要，不把用户名原文写入 Key。
- 支持维度：IP、User、Route、Resource、Action；调用方通过 `identity`、`route`、`resource`、`action` 组合策略。
- 超限返回 `429` 和 `Retry-After`。
- Redis 不可用时由调用方决定降级策略；登录入口当前采用 fail-open，避免 Redis 故障导致管理员无法登录，同时保留日志和后续告警扩展点。

## 3. JWT 生命周期

- Access Token 增加 `typ=access` 和 `jti`。
- Refresh Token 使用独立 TTL，增加 `typ=refresh` 和 `jti`。
- `/api/v1/auth/refresh` 校验 Refresh Token、用户状态后轮换 Token，并撤销旧 Refresh Token。
- `/api/v1/auth/revoke` 撤销 Refresh Token；撤销记录按 Token 剩余 TTL 写入 Redis。
- 旧 Access Token 的兼容解析保留，但 Refresh Token 不能用于访问业务接口。

## 4. 密码安全

- 保持 PBKDF2-HMAC-SHA256 哈希格式，禁止日志输出明文密码或 Token。
- 密码策略参数配置化：`PASSWORD_MIN_LENGTH`。
- 后续用户创建/修改密码入口必须调用统一密码策略校验和哈希适配器，不允许保存明文密码。

## 5. 非目标

- 本阶段不引入新的 JWT/密码第三方库。
- 不把认证和限流合并为大型全局 Middleware。
- 不实现 OAuth/OIDC、MFA、设备管理和密码找回流程。
