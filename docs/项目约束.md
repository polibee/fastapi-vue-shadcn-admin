# FastAPI Vue Admin 项目约束

**状态：** 当前开发唯一约束基线  
**适用范围：** `server/`、`admin/`、`worker/`、生成器和所有业务 Module

## 1. 架构原则

项目定位为 FastAPI + Vue 3 + TypeScript 的通用 Admin Framework。Core 提供通用能力，Module 实现业务。

唯一允许的依赖方向：

```text
Business Module → Admin Core → Infrastructure
```

禁止 Core 依赖具体业务，禁止业务 Module 直接修改其他 Module 的数据表。

### 1.1 目录规则

```text
server/app/
├── core/                 # 框架能力和基础设施适配
├── modules/              # 垂直业务模块
│   ├── users/
│   ├── roles/
│   ├── permissions/
│   └── ...
├── shared/               # 真正跨模块且无业务归属的代码
└── main.py               # 应用组装，不写业务逻辑
```

采用严格的 Vertical Module + Internal Layer：

```text
modules/users/
├── module.py
├── model.py
├── schema.py
├── repository.py
├── service.py
├── router.py
├── resource.py
├── permissions.py
├── events.py
├── locales/
│   ├── zh-CN.json
│   └── en.json
└── tests/
```

不新增全局 `app/models`、`app/repositories`、`app/services`、`app/api` 作为业务代码收容目录。既有代码如位于这些目录，迁移到对应 Module 时必须单独记录，不得在新增功能中继续扩大旧结构。

每个 Module 的 `module.py` 负责注册 Router、Permission、Navigation、Resource、Event 和 Task。

## 2. 后端与数据库

- Python 3.13+、FastAPI、Pydantic v2、SQLAlchemy 2.x Async ORM、Alembic。
- 默认支持 PostgreSQL，并保持 MySQL 兼容；只切换 `DATABASE_URL`，不修改业务代码。
- ORM Model、Pydantic Schema、Repository、Service、Router 必须分层。
- 调用链固定为 `Router → Service → Repository → SQLAlchemy → Database`。
- 普通业务禁止 Raw SQL；查询使用 SQLAlchemy ORM 或 Expression Language。
- 数据库结构只能通过 Alembic 修改；迁移必须人工 Review。
- 默认只使用 PostgreSQL/MySQL 交集能力，禁止未经批准使用 `JSONB`、`ILIKE`、`SKIP LOCKED` 或数据库专有 DDL。
- 时间统一使用 UTC timezone-aware 类型；字符串字段显式声明长度。

## 3. API 与前端契约

- Pydantic → FastAPI → OpenAPI → Generated TypeScript SDK 是唯一 API Contract。
- 前端不得手写重复 API Client、业务 API Type 或 `/api/...` 字符串。
- API 使用版本化路径，例如 `/api/v1/users`。
- 错误响应必须包含稳定的机器可读 `code`，前端不得依赖错误文案判断逻辑。
- Scalar 只消费 `/openapi.json`，不维护第二份接口定义。
- 业务模块必须提供对应的 OpenAPI Tag。

## 4. UI 约束

- `components/ui/` 只放官方 shadcn-vue 源码。
- `components/ai-elements/` 只放 AI Elements Vue 源码。
- `components/admin/` 放后台语义和逻辑组合组件。
- `components/ui-extensions/` 只允许补充官方确实没有的组件。
- 禁止引入第二套 UI Framework，禁止重复实现 Button、Input、Dialog、Table、Dropdown、Tooltip。
- 未有明确产品需求，不得修改 shadcn-vue 的配色、Radius、Shadow、CSS Variables、Design Token 或视觉语言。
- 功能开发不授权无关 UI 重设计；相关 PR 必须说明 UI 基线变更原因。

## 5. 认证、权限与安全

- 认证使用 FastAPI Dependency，不实现巨型 Auth Middleware。
- RBAC 和 Data Scope 必须由后端强制执行；隐藏菜单不算权限控制。
- Module 之间通过 Service Interface 或 Event 协作，不直接访问对方 Model 或数据表。
- 密码只能保存哈希；日志、审计、Task args、AI 消息不得保存 Token、API Key、Authorization、密码等 Secret。
- 健康检查不得泄漏数据库密码或完整连接串。
- 导入、导出和批量操作必须经过 Schema Validation、Permission 和 Service。

## 6. 中间件、缓存与任务

- 优先复用 FastAPI/Starlette 已有的 CORS、Trusted Host、GZip、Exception Handler、Dependency、Lifespan 和 BackgroundTasks。
- 自定义 Middleware 只实现 Request ID、Request Context、Access Log、Timing 和 Security Headers 等框架能力。
- CORS、认证、RBAC、业务逻辑、数据库访问不得混成一个 Middleware。
- Redis 通过统一 Infrastructure Adapter 提供；Cache、Rate Limit、Lock、Task Engine 不得各自创建 Redis Client。
- Redis 不可用时，基础 Web、登录、标准 CRUD、OpenAPI 必须仍可用。
- BackgroundTasks 只处理轻量后处理；长任务、导入导出、可靠重试使用 Task Engine。
- Task Engine 使用 PostgreSQL/MySQL 任务记录与 outbox，Redis/arq 作为执行通道；任务处理必须幂等。

## 7. Resource Engine 与 Generator

- Database Contract、API Contract、Admin UI Contract 分别只有一个事实来源：SQLAlchemy/Alembic、Pydantic/OpenAPI、ResourceDefinition/Manifest。
- Resource Engine v1 先稳定 Contract、Manifest Compiler、Renderer Registry，再开发 Generator。
- v1 不做可视化 Resource Designer、复杂公式 DSL、动态 JavaScript、完整 Low-Code、插件市场和拖拽表单设计器。
- Generator 必须幂等、可重复执行，并通过 Snapshot/Golden File Test。
- 生成代码和人工代码必须有清晰边界，Generator 不得覆盖人工业务实现。

## 8. 多语言

- 多语言从 Module 开发第一天启用 i18n。
- 每个 Module 必须提供 `locales/zh-CN.json` 和 `locales/en.json`。
- 页面、表单、错误提示、菜单、权限名称和通知文本禁止硬编码用户可见字符串。
- 新增或修改用户可见文本时，两个默认语言包必须同步更新。
- Admin 前端语言包必须使用 JSON namespace，不得恢复单一全局 `zh-CN.json` / `en.json`。
- 前端目录统一采用 `admin/src/locales/{locale}/{namespace}.json`，其中 locale 为 `zh-CN` 或 `en`。
- `common`、`shell`、`auth` 等基础 namespace 可在启动时加载；业务 namespace 必须通过 locale loader 按路由动态加载。
- `admin/src/locales/index.ts` 只允许负责加载、合并和切换语言，不得在 TypeScript 中保存翻译内容。
- 中英文 namespace 的顶层 key 必须保持一致，并由测试校验；翻译内容只允许存放在 JSON 文件中。

## 9. 测试与质量门禁

后端使用 Ruff、Pyright/mypy、pytest；前端使用 ESLint、TypeScript/Vue Type Check、Prettier。

核心能力必须覆盖 Unit、Integration、API Contract、Frontend Component，关键流程再增加 E2E：

- Auth/RBAC
- Resource Engine
- Generator Snapshot
- OpenAPI → SDK
- Alembic upgrade/downgrade/upgrade
- PostgreSQL/MySQL 双库
- Redis 不可用降级
- Secret 脱敏

任何阶段只有在对应门禁全部通过后才能进入下一阶段。

## 10. AI Coding 约束

每次开发前必须按顺序：

```text
确认 Module → 阅读 Core Interface → 检查已有组件 → 检查 OpenAPI Contract
→ 复用 Infrastructure → 实现 → 更新 SDK/迁移 → 类型检查 → 测试 → 构建验证
```

AI 不得为了完成单个功能重构项目、绕过 Repository/RBAC、引入未经批准的框架、手写重复 API Client、修改无关 UI 或删除兼容代码。
